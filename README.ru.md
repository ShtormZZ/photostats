# Статистика фотоархива

Собирает EXIF со всех фотографий в указанных папках и показывает распределения
в браузере. По любому столбику можно щёлкнуть и увидеть сами снимки.

## Установка и запуск

Запустите **photostats.bat** двойным щелчком. Он найдёт Python, при первом
запуске сам развернёт окружение и поставит библиотеки, а затем откроет окно с
тремя проходами и кнопкой открытия интерфейса. Больше руками ставить нечего.

Если Python не найден, файл об этом скажет и покажет ссылку. Берите с
[python.org](https://www.python.org/downloads/windows/), при установке отметьте
«Add python.exe to PATH» и не снимайте «tcl/tk and IDLE» — на нём построено окно.

Желательно, хотя и не обязательно, поставить [ExifTool](https://exiftool.org):
без него не читаются RAW и фирменные теги объективов.

```
winget install -e --id OliverBetz.ExifTool
```

### Окно

Шаги пронумерованы, под каждой кнопкой написано, что она делает, а строка
вверху подсказывает следующий шаг исходя из того, что уже есть в базе, —
гадать, что нажимать, не приходится.

Папки с фотографиями добавляются один раз и запоминаются. Дальше три кнопки:

- **Read EXIF** — быстрый проход, его достаточно, чтобы интерфейс заработал.
  Галочка «include RAW and DNG» включает RAW; по умолчанию только JPEG, потому
  что RAW обычно лежит рядом с JPEG того же кадра и считался бы дважды.
  Читаются ровно `.jpg` и `.jpeg`, а файлы мельче 50 КБ пропускаются — это
  эскизы и картинки из переписки, они только портят статистику. Порог меняется
  ключом `--min-size`.
- **Analyse images** — цвет, яркость, контраст, потери. Заметно дольше:
  раскодируется каждый файл.
- **Sign files** — подписи содержимого для точного поиска дубликатов.
- **Check a folder** — выберите папку, которую вы ещё *не* сканировали, и проход
  скажет, сколько в ней уже знакомого. Подробнее ниже.
- **Open interface** — поднимает сервер и открывает браузер.

**Проходы и сервер работают одновременно.** Можно смотреть, как наполняется
статистика, пока анализ ещё идёт. Остановка сохраняет сделанное, и следующий
запуск продолжит с того же места — длинный разбор можно делать в несколько
подходов.

### Из командной строки

Окно — это удобство, а не замена. Всё по-прежнему доступно напрямую:

```
python scan.py "D:\Фото" "E:\Архив 2001-2010"    # EXIF
python scan.py --colors-only                       # изображения
python scan.py --hash-only                         # подписи
python scan.py --check-dups "E:\Карта"             # проверка, без записи
python app.py                                      # интерфейс
```

### Проверить папку, прежде чем добавлять

Панель дубликатов отвечает на вопрос про то, что уже в архиве. Тот же вопрос
возникает раньше: карта из фотоаппарата, чужой диск, папка `фото_бэкап_финал` —
есть ли там что-то новое или всё это уже лежит дома?

```
python scan.py --check-dups "E:\Карта"
```

Или кнопка **Check a folder** в окне. Каждый файл папки опознаётся тем же
правилом, каким считает дубликаты интерфейс, и ищется в базе. В конце — итог:

```
Checked 812 files in 41 s.
  duplicates: 763
    749 already in the archive, 14 repeated inside the folder itself
  new:        49

Nothing was written to the database.
```

**В базу не пишется ничего.** Она открывается только на чтение, так что проход
не может дописать в неё даже по ошибке, — ради этого он и нужен. Посмотрели
числа и решили: сканировать папку по-настоящему или не стоит.

Файлы, которые лежат в базе *по тому же самому пути*, считаются отдельно, как
`already scanned`: это не копии архива, это и есть архив. Строка появляется,
если проверить папку, которую вы уже сканировали.

Правило берётся то, которым интерфейс пользуется сейчас, и проход его называет.
По подписям читается 128 КБ на файл и находятся переименованные копии; по имени,
размеру и времени съёмки приходится читать EXIF каждого файла — это медленнее, а
переименованная копия проскочит. Размен тот же, что и у панели дубликатов:
сделайте `--hash-only`, и проверка тоже станет строгой.

## Что показывает

Панели слева собраны в три блока — заголовок блока сворачивает и разворачивает
его целиком. Счётчик рядом с заголовком считает панели с данными: часть скрыта,
пока не сделан разбор изображений или пока в базе один формат файлов.

**Время съёмки** — хронология, месяцы года, время суток.
**Оценка и теги** — звёзды из EXIF, ваши собственные пометки и до трёх слов на
снимок, см. ниже.
**Метрики EXIF** — камеры, объективы, параметры съёмки, а также формат и размер
файла: они берутся не из EXIF, но описывают файл, а не его содержимое.
**Метрики изображения** — всё, что получено разбором пикселей.
**География** — места съёмки по координатам из EXIF.

| Оценка | звёзды 1–5, «плохая» и «5+»; ваша оценка перекрывает камерную |
| Теги | до трёх слов на снимок, ваши собственные; выбор нескольких — «любой из них» |
| Хронология | плёночная лента, один кадр — один месяц съёмки; клик по году — отбор за год |
| Месяцы года | 12 столбцов, все годы вместе |
| Время суток | 24 столбца, ночные часы на затемнённой дорожке |
| Бренды камер | нормализованные: `NIKON CORPORATION` и `Nikon` — это одно и то же |
| Модели камер | полное имя с брендом без дублирования |
| Объективы | `LensModel`, при отсутствии — `LensID` / `LensType` из фирменных тегов |
| Фокусные расстояния | диапазоны; переключатель «в эквиваленте 35 мм» |
| Диафрагма | диапазоны по ступеням: f/2.2 – f/2.8, f/4.5 – f/5.6 и так далее |
| Выдержка | от «короче 1/4000» до «30 с и длиннее» |
| Светочувствительность | диапазоны ISO по ступеням |
| Размер файла | от «до 0,5 МБ» до «свыше 64 МБ» |
| Камера во времени | появляется, когда камера выбрана: даты, срок службы, помесячная лента |
| Объектив во времени | то же по выбранному объективу |
| Форматы файлов | появляется, только если в базе больше одного формата |
| Места съёмки | скопления координат: список всегда, карта по кнопке |
| Основной цвет | одиннадцать групп плюс «разноцветный», с образцами оттенка; собирается отдельно, см. ниже |
| Цвет в центре кадра | подпункт основного цвета, показывается вместе с ним |
| Цветность | цветные и чёрно-белые кадры |
| Яркость кадра | от «очень тёмных» до «очень светлых» |
| Контраст | от плоского до высокого |
| Потери в светах и тенях | выбитое в белое, провалившееся в чёрное, и то и другое |

### Оценка

Звёзды читаются из EXIF самого файла — тег `Rating`, тот самый, что пишет
фотоаппарат по нажатию кнопки со звездой и что показывает проводник Windows.
Больше ничего не читается: Lightroom держит звёзды в `xmp:Rating` или в своём
каталоге, поэтому снимок, оценённый только в Lightroom, приходит сюда без оценки.

Оценку можно поставить и здесь, поверх камерной. Наведите курсор на миниатюру в
полосе предпросмотра или раскройте строку списка — там появится ряд: красный
**✗** для неудачного кадра, **от одной до пяти звёзд** и **5+** для тех, что
стоят особняком. Одновременно может гореть только одно, поэтому всё и стоит
одним рядом; повторный щелчок по выставленному снимает оценку.

**Ваши оценки идут в базу и никуда больше.** В файлы ничего не пишется. Снимете
свою оценку — снимок вернётся к тому, что сказал EXIF, так что камерные звёзды
не теряются.

В панели шкала идёт от лучшего к худшему, и в ней только выставленные оценки:
неоценённых в любом архиве большинство, и полоска для них задавала масштаб всем
остальным — пять звёзд превращались в чёрточку в пиксель. Чтобы разобрать
неоценённое, отсортируйте выборку по оценке в списке «sort»: неоценённые идут
первыми. Тот же ряд есть в карточке снимка, справа от фотографии.

Щелчок по миниатюре открывает карточку снимка. **Двойной щелчок по самой
фотографии разворачивает её на всё окно браузера** — без карточки и подписей,
одна фотография; для этого подгружается копия покрупнее. Второй двойной щелчок
или Escape возвращают карточку, ещё один Escape закрывает её.

Стрелки у левого и правого края фотографии — или клавиши **←** и **→** —
листают выборку, не возвращая в список. Листается тот набор, из которого
карточка открыта: отсортированный список, если открыли из строки, и те самые
десять случайных, если из полосы предпросмотра. Список загружается страницами,
и шаг за конец загруженного подтягивает следующую страницу, а не упирается в
стену. На краях выборки стрелка, которой некуда вести, не показывается. В
полноэкранном виде они тоже работают — там листание и есть основное занятие.

Хронология техники показывает только выбранную камеру или объектив: пока
ничего не выбрано, в панели стоит подсказка и запрос на сервер не уходит.
Выберите камеру в панели «Модели камер» — и увидите даты первого и последнего
кадра, срок в работе, число снимков и помесячную ленту.

Лента по умолчанию обрезана до периода работы плюс полгода запаса с каждой
стороны. У камеры, прожившей один год, в архиве на двадцать лет остальные ячейки
были бы пусты, и разглядеть в них нечего. Переключатель «весь архив» в шапке
карточки возвращает полный ряд месяцев — он полезен, когда нужно понять, куда
камера попадает в общей истории и чем снимали до и после неё.

Высота столбика — доля месяца, снятая этой техникой, а не число снимков: иначе
годы редкой съёмки выглядели бы перерывом в использовании. Клик по столбику
отбирает этот месяц, клик по году под лентой — весь год.

Ячейки месяцев делят ширину карточки поровну, а не стоят фиксированными:
короткий период больше не занимает угол широкого экрана. У ячейки есть потолок
ширины, чтобы три месяца не расплылись в три лопаты, — если период совсем
короткий, лента становится уже карточки и встаёт по центру. Ось лет делится
в тех же долях, а подпись года появляется, только когда под неё есть место.

Срок в работе считается по датам съёмки первого и последнего кадра, оба крайних
дня включительно. Это календарный промежуток, а не число дней, когда вы
действительно снимали, — для второго рядом указано число активных месяцев.

Фильтры складываются: выбрали Canon → графики объективов и фокусных
показывают только его; выбрали ещё июль → останутся июльские кадры на Canon.
Каждый график при этом продолжает показывать своё измерение целиком,
чтобы было куда переключиться.

Справа — выборка: сверху десять случайных снимков из неё (кнопка «другие»
перетасовывает), ниже полный текстовый список — время съёмки, файл, теги,
камера, объектив, фокусное.

Клик по строке раскрывает под ней миниатюру и краткую сводку: дата, техника,
параметры съёмки, цвет с образцом оттенка, свет, размер и полный путь. Рядом
кнопки «в проводнике», «открыть файл», «вся папка» и «крупно». Раскрытые строки
друг друга не закрывают — можно развернуть несколько кадров подряд и сравнить
их, не теряя места в списке. При смене фильтра список строится заново, уже
свёрнутым.

Списком, а не сеткой миниатюр, — намеренно: браузер держит к серверу не
больше шести одновременных соединений, и сотня картинок занимала бы их все,
из-за чего клики по графикам переставали отзываться. Сейчас миниатюры
грузятся по одной и только для десяти снимков, а при смене фильтра
незавершённые загрузки отменяются.

Текущую выборку можно выгрузить в CSV.

### Теги

На снимок вешается **не больше трёх тегов**: одно слово каждый, буквы и цифры,
без пробелов и знаков препинания. Алфавит любой — `море` такой же тег, как
`sea`, — и всё хранится строчными, так что `Море`, `МОРЕ` и `море` это один тег,
а не три.

Раскройте строку списка или откройте карточку снимка: под оценкой стоит поле
ввода. По мере набора под ним появляются уже заведённые теги с числом снимков
на каждом — выберите готовый, и слово не размножится на почти одинаковые
варианты. Подсказки берутся из всего архива, а не из текущей выборки, поэтому
тег, которым помечено что-то за пределами фильтра, всё равно предложится. Enter
принимает набранное, стрелки ходят по списку, **×** на чипе снимает тег.

Ограничение в три — это и есть суть. Снимок с дюжиной тегов не найдёт уже никто,
а три помещаются в строку всюду, где показываются: в списке, в раскрытой строке
и в карточке.

В панели теги идут по числу снимков. Снимков без тегов среди строк нет: пока
архив размечается, их там почти весь архив, и полоска для них оставила бы от
настоящих тегов чёрточки, которые не с чем сравнить. Выбор нескольких тегов
показывает снимки с **любым** из них, как и во всех остальных панелях. В выгрузку
CSV теги попадают отдельной колонкой.

**Теги идут в базу и никуда больше.** В файлы ничего не пишется. Они лежат в
отдельной таблице, которой не касается ни один проход сканера, так что повторное
чтение метаданных их не сотрёт; а снимок, удалённый с диска, уносит свои теги с
собой, когда сканер убирает строку. Перенос файла в другую папку — это новый
путь и, значит, новый снимок для базы: теги при этом теряются, как теряется и
оценка, и по той же причине.

## Места съёмки

Координаты берутся из EXIF — их пишут телефоны и камеры со спутниковым
приёмником. Если архив снят зеркалкой без GPS, панель останется пустой; в шапке
всегда видно, у скольких снимков координаты есть.

Близкие точки собираются в места прямо в запросе, сеткой по градусам. Ползунок
меняет размер ячейки: в крупном масштабе получаются города, в мелком — районы
и отдельные улицы. Клик по месту отбирает снимки этой области, и дальше
работают все остальные панели: можно посмотреть, чем и когда вы там снимали.

Клик по месту — в списке или по кружку на карте — приближает карту к нему и
подсвечивает кружок. Карта при этом не пересоздаётся: прокрутка и масштаб,
выбранные вручную, сохраняются, а подвод к точке происходит только в момент
смены выбора.

**Карта грузится только по кнопке.** Это единственное обращение программы
наружу за всё время работы: подложка берётся с openstreetmap.org, библиотека
карты — с unpkg.com. По запросам тайлов их серверы видят, какие районы вы
разглядываете, — для личного архива это стоит понимать заранее. Список мест
со всеми теми же кластерами и отбором работает без сети, поэтому кнопку можно
не нажимать вовсе.

Координаты попадают в выгрузку CSV отдельными колонками — если захочется
построить карту в чём-то стороннем.

## Если что-то не так

**Лента хронологии растянута на десятилетия.** Так быть уже не должно: лента
строится только по годам с 1990 до следующего от текущего. Снимки со сбитой
датой (сброшенные часы камеры дают и 1970, и 2052 год) в неё не попадают, но из
базы никуда не деваются — под лентой появляется строка с их числом и ссылкой
«показать их». Нижнюю границу можно сдвинуть: `app.py --min-year 1980`.
Это единственный способ такие снимки найти, поэтому строка не убирается.

**В базе нет координат, хотя снимки с GPS.** Набор полей EXIF расширяется вместе
с программой, и старые базы этого не знают. Сканер сам замечает расхождение и
перечитывает метаданные — разбор изображений при этом сохраняется, цвет и свет
заново считать не придётся.

**Часть фотографий свалена в один месяц.** У них нет `DateTimeOriginal` —
взята дата изменения файла. Сколько таких, пишет `scan.py` в конце.
В карточке снимка такая дата помечена «(из даты файла)».

**Свет посчитан не у всех.** Если архив разбирался предыдущей версией, у старых
записей есть цвет, но нет яркости и контраста. Повторный запуск
`scan.py --colors-only` дочитает только их, уже посчитанное не трогая.

**Цвет у RAW не определился.** Пиксели RAW Pillow не читает — нужен ExifTool,
тогда берётся встроенное превью. Такие файлы помечены группой «не определён»,
и повторный запуск прохода их не трогает: чтобы переразобрать, выполните
`UPDATE photos SET color=NULL WHERE color='не определён'` в любом SQL-клиенте.

**Нет миниатюр у RAW.** Нужен ExifTool — превью достаётся из самого
RAW-файла. Если он установлен, а миниатюр всё равно нет, проверьте
`exiftool -ver` в той же папке.

**Кадров вдвое больше, чем ожидалось.** Значит, архив просканирован с `--raw`,
а съёмка велась в RAW+JPEG. Отберите один формат в карточке «Форматы файлов»
или пересоберите базу с ключом `--full` без `--raw`.

**Сканирование идёт медленно.** Основное время — чтение EXIF. `--workers 8`
ускоряет на быстрых дисках; на сетевой шаре или внешнем HDD помогает мало.

**Съедено место.** Миниатюры кешируются в `cache\thumbs`. Папку можно
удалять в любой момент, она наполнится заново.

## Файлы

```
photostats.bat  единственная точка входа
launcher.py     окно: окружение, задачи, сервер
scan.py         обход папок, EXIF, разбор изображений, подписи -> photos.db
app.py          локальный сервер: агрегация, миниатюры, открытие файлов
web/            интерфейс (один HTML, без внешних зависимостей) и иконка
photos.db       база SQLite — её можно открыть любым SQL-клиентом
settings.json   пути к вашим папкам; в репозиторий не попадает
```

Иконку рисует `python tools/make_icon.py`: форма задана числами в самом
скрипте, файлы лежат в `web/` и закоммичены — запускать его нужно только
после правки этих чисел.
